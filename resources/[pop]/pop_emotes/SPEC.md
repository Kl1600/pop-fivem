# pop_emotes

Compact menu for original selections from built-in GTA animations. Choose, mark favourites, or cancel an emote. A two-person handshake requires explicit consent. No RPEmotes content, streamed props, ped clones, or teleporting.

- Files: `fxmanifest.lua`, `config.lua`, `client/main.lua`, `server/main.lua`, `README.md`, ten locales, unchanged Bridge/shared/kit, `web/{index.html,script.js,style.css}`.
- Config defaults: `MenuKey='F3'`, `CancelKey='X'`, `InviteDistance=2.5`, `InviteSeconds=15`, `InviteCooldown=5`. `Catalog` maps safe IDs to locale keys, built-in dictionaries/clips, positive durations and flags; only the configured handshake entry is shared.
- Commands `popemotes` and `popemotes_cancel`; exports `GetCurrentEmoteName()`, `Play(id)` for solos, and `Stop()`. Favourites use a local player KVP. Cancel on move into a vehicle, death, cuffing, resource stop or ped replacement. Check animation dictionary, bounded load, no threads while idle. Stop only the animation started by this resource.
- Server callbacks `pop_emotes:invite(target,id)`, `pop_emotes:respond(ticket,accept)` return `ok, reason?`. Validate loaded players, same routing bucket, server distance, alive, on foot and no cuffs. Use bounded IDs and one invitation per participant, and one per sender each configured interval, with both players reserved during an accepted shared animation. Store identities across the invitation and clear on action, expiry or disconnect. Recipient is inferred from callback source. No client-supplied dicts, player positions or event names. `pop_emotes:client:invite(ticket, name, id, timeout)`, `pop_emotes:client:inviteClosed(ticket)` and `pop_emotes:client:play(id, target, responder)` are server-to-client.
- NUI `pop_emotes:menu` carries the catalogue, favorites and current selection; `pop_emotes:invite` carries the offer; `pop_emotes:close` releases menu focus; `pop_emotes:inviteClosed` clears consent controls. NUI posts `play { id }`, `favorite { id }`, `respond { ticket, accept }`, `stop`, and kit `close`. Shared action uses the nearest local candidate; server rechecks at invite and accept. No auto-acceptance.
- Locales add labels for menu, favourites, animation names, invitations, cancellation and failures, keeping kit keys and Arabic RTL. No SQL required.
